# Moneymaker Research Director: LLM Observer Architecture

## 1. System Role & Design Philosophy
The **Moneymaker Research Director** is a dedicated, read-only AI research observer layer engineered to assist quantitative researchers, analyze trading sessions, detect feature/execution drift, and formulate testable challenger hypotheses.

It operates strictly **outside the capital control path**:
```
[Market Data / Broker / Execution Engine]
                  │
                  ▼ (Read-Only Structured Telemetry)
       ┌──────────────────────────────────────┐
       │   Moneymaker Research Director       │
       │   (Read-Only LLM Observer Layer)     │
       ├──────────────────────────────────────┤
       │ • Daily Session Reviews              │
       │ • Anomaly & Drift Detection          │
       │ • RAG Governance Knowledge Base      │
       │ • Challenger Hypothesis Generation   │
       └──────────────────────────────────────┘
                  │ (Markdown / Structured JSON)
                  ▼
         [Human Quantitative Researcher]
```

---

## 2. Core Architectural Subsystems

### A. Structured Input Adapters
The Research Director ingests structured, type-safe data objects rather than unbounded database queries:
- `SessionSummary`: Session date, trade count, realized PnL, gross/net returns, symbols traded.
- `ModelHealthSummary`: Spearman Rank IC, $p$-value, meta-label precision, CUSUM status, feature drift metrics.
- `ExecutionQualitySummary`: Spreads, implementation shortfall, live slippage penalty, fill rates, operator latency.
- `RiskSummary`: Capital ceiling, margin metrics, reconciliation records, daily loss limits.

### B. Output Schema Taxonomy
The Research Director produces structured outputs adhering to `LLMOutputType`:
1. `SESSION_REVIEW`: Daily executive operational summary.
2. `ANOMALY`: Flagged outliers in spread, shortfall, or model performance.
3. `DRIFT_WARNING`: Statistical warnings on feature or calibration divergence.
4. `RESEARCH_HYPOTHESIS`: Mechanistic explanations for observed market phenomena.
5. `CHALLENGER_EXPERIMENT`: Testable offline research specifications.
6. `MODEL_CRITIQUE`: Quantitative critique of ranking or meta-label performance.

---

## 3. Provenance & Hallucination Prevention

Every factual statement produced by the Research Director is tagged with a `DataProvenanceType`:
- `OBSERVED_DATA`: Directly measured execution prints, fills, and broker balances.
- `MODEL_PREDICTION`: Inferences generated by the frozen ML pipeline.
- `STATISTICAL_INFERENCE`: Calculated confidence intervals, $p$-values, Rank IC.
- `RESEARCH_HYPOTHESIS`: Speculative causal propositions requiring empirical testing.

**Fail-Closed Refusal**: If required data is missing or unindexed, the system outputs `UNKNOWN` rather than hallucinating prices, balances, or performance metrics.
